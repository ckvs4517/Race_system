# Spin League

一套為戰鬥陀螺活動設計的 Web 賽事管理系統。觀眾可以公開查看賽程，主辦方則能建立賽事、安排對戰、輸入比分並管理排行榜。

[開啟線上版本](https://spin-league-tournament.ckvs4517.chatgpt.site)

## 主要功能

- 單淘汰賽，以及「四輪預賽＋資格加賽＋四強循環決賽」瑞士制
- 單淘汰支援 2～32 位、瑞士制支援 4～32 位、1～8 台戰鬥台
- 建立、編輯、複製與刪除賽事
- 可先建立空白賽事，並從該賽事頁一鍵開放、複製或分享專屬公開報名連結
- 公開報名包含選手名稱、電話、備註與可擴充自訂欄位；後台核准後才加入正式名單
- 保留後台手動輸入選手名單
- 賽前名單支援搜尋、報到狀態篩選、快速新增，以及先進入管理模式再批次移除；開賽只採用已報到選手
- 名稱搜尋會與「全部／未報到／已報到」套用交集條件，不會混入其他報到狀態
- 報到階段完全不產生賽程；確認報到後才進入獨立排程階段，支援重新隨機分組與逐場手動調整首輪對戰
- 關閉公開報名或進入排程時會更換安全 token，原報名網址立即失效
- 賽事頁顯示「建立、招募、報到、賽程、比賽、完成」進度，手機版只保留當下主要操作，其餘收進更多選單
- 公開活動資訊：日期、報到與開賽時間、地點、地址、地圖、原始貼文及備註
- 賽事清單依活動日期排列，活動資訊同步匯出至 CSV
- 隨機分組、種子、輪空與自動晉級
- 正式比賽與獨立記分板
- 棄賽、未出席與中途退賽判定
- 即時排行榜依勝場、敗場與總得分排序
- 四強確認只顯示排行榜前四名；已完成輪次預設收折
- 進入四強循環決賽後，主賽程只顯示四強輪次，前面賽事資料仍保留於後台及匯出檔
- 四強循環決賽固定使用一台戰鬥台，不受預賽台數設定影響
- 多位裁判同步與資料衝突保護
- 記分、判負、重賽、報到、分組與晉級等正式操作由後端驗證，前端不再上傳整包賽事
- 賽程頁只同步目前賽事，未變更時使用 ETag 省略重複下載與重繪
- JSON 備份／還原與 CSV 報表
- 完賽後可下載包含全部輪次、選手與比分的高解析 PNG 賽程圖
- 手機與桌面響應式介面

## 主辦方快速流程

1. 登入後建立賽事；參賽名單可以先留空。
2. 進入賽事，按「建立公開報名連結」，設定名額後分享給選手。截止時間可留空，賽事開始時仍會自動停止收件。
3. 從「查看報名名單」核准報名，或在參賽名單按「新增選手」加入現場選手。
4. 使用搜尋與報到狀態篩選找到選手並勾選報到。需要刪除時先按「管理名單」，勾選後再確認移除。
5. 按「確認報到，進入排程」，再進行隨機分組；必要時逐場調整首輪對戰，最後確認賽程並開始記分。

網站導覽列的「使用說明」也提供同一套手機操作流程。

從單一賽事按「查看報名名單」進入時，返回按鈕會回到原賽事；從上方「報名管理」進入時，則會回到賽事選擇畫面。

## 技術特色

前端使用原生 HTML、CSS 與 JavaScript ES Modules，後端使用 Cloudflare Worker 與 D1。正式賽事操作採用後端 command API 與 revision 樂觀鎖，前端只負責畫面、輸入與同步狀態。專案不依賴前端框架，適合下載後閱讀、修改或延伸新的賽制。

## 賽事規則

專案內附 [Beyblade X 賽事規則 v12（2026）](beyblade-x-rules-v12-2026.pdf)，可供主辦方與後續功能開發參考。網站目前的判定仍以系統內已實作的規則為準，並不代表 PDF 中的所有計分細節都已自動套用。

## 開始修改

```bash
git clone https://github.com/ckvs4517/Race_system.git
cd Race_system
```

前端需透過 HTTP 載入 ES Modules，可使用 VS Code Live Server 預覽。完整的架構、資料格式、測試與部署方式請閱讀 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 自動測試

每次推送都會由 GitHub Actions 測試單淘汰與新版瑞士制、公開報名／審核、完整主辦方操作流程、API、多人同步及部署建置。最新結果可在 [Actions](https://github.com/ckvs4517/Race_system/actions) 查看。
